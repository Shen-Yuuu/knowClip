## 开发规范

### 代码规范

1. **类型安全**
   - ❌ 禁止 `any`、`as any`
   - ❌ 禁止未经校验的 `JSON.parse`
   - ❌ 禁止非空断言 `!`
   - ✅ 使用类型守卫和类型谓词

2. **错误处理**
   ```typescript
   // ❌ 错误示例
   let result = JSON.parse(jsonString);
   
   // ✅ 正确示例
   function parseJSON<T>(jsonString: string): T | null {
     try {
       const result = JSON.parse(jsonString);
       // 进一步校验 result 结构
       return result as T;
     } catch (error) {
       hilog.error(DOMAIN, TAG, `JSON parse error: ${error}`);
       return null;
     }
   }
   ```

3. **命名规范**
   - 文件名：小驼峰 `userService.ets`
   - 类名：大驼峰 `KnowledgeItem`
   - 常量：全大写 `MAX_IMAGE_SIZE`
   - 接口：大驼峰 + `I` 前缀 `IKnowledgeRepository`

4. **注释规范**
   - 公开 API 必须写 JSDoc
   - 复杂逻辑必须写行内注释
   - TODO 必须注明责任人和日期

## 风险管理

### 技术风险

| 风险 | 影响 | 概率 | 应对策略 |
|------|------|------|---------|
| CoreVisionKit OCR 识别率低 | 高 | 中 | 允许用户手动编辑，提供"重新识别"功能 |
| FTS4 不可用 | 中 | 中 | 降级到 LIKE + 关键词索引方案 |
| URI 内容丢失 | 高 | 低 | 及时复制到私有目录，添加校验 |
| 存储空间不足 | 中 | 低 | 提示用户清理，提供缓存清理功能 |
| 系统分享面板无法获取来源应用 | 低 | 中 | 仅记录系统提供的信息，不伪造 |

---

### 进度风险

| 风险 | 应对策略 |
|------|---------|
| 技术验证失败 | 第 0 阶段设置 Go/No-Go 决策点，及时调整 |
| OCR 性能不达标 | 引入批量处理队列，降低用户感知延迟 |
| 搜索方案选择困难 | 两套方案都实现原型，真机对比测试 |
| 真机测试环境不足 | 准备多台设备，不同 HarmonyOS 版本 |

## Go/No-Go 决策标准

### 第 0 阶段 → 第 1 阶段

**必须全部通过**：
- ✅ 原型 A：系统分享接收至少 8/10 场景通过
- ✅ 原型 B：OCR 识别至少 15/20 张图片成功
- ✅ 原型 C：中文搜索方案选定且性能达标

**可接受的不完美**：
- ⚠️ OCR 识别率 70-90%（允许用户编辑）
- ⚠️ 搜索召回率 80-95%（渐进优化）
- ⚠️ 无法获取来源应用名称（非核心）

**不可接受的失败**：
- ❌ 系统分享完全无法接收
- ❌ OCR 全部失败或崩溃
- ❌ 中文搜索完全不可用
