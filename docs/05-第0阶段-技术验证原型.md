# 第 0 阶段：技术验证原型

## 1. 阶段目标

本阶段只验证三个决定项目可行性的技术假设：

1. 第三方应用能否通过系统分享把图片、文本和链接交给知微，并在分享 URI 权限回收前复制到应用私有目录。
2. CoreVisionKit 能否在目标真机上稳定识别常见中文截图。
3. RDB 的 LIKE 基线搜索能否在早期数据规模下满足中文检索需求。

本阶段不实现完整知识库产品功能。

## 2. 当前实现状态

2026-08-28 已完成源码修正并通过 Hvigor 调试构建，ArkTS 为 0 errors。构建通过只证明代码与当前 API 21 SDK 兼容，不代表三项技术已经真机验证通过。

### 原型 A：系统分享接收

当前实现：

- ShareExtensionAbility 和 type: share 注册
- systemShare.getSharedData 强类型解析
- LocalStorage 向分享确认页传递数据
- 分享扩展存活期间复制图片到应用私有目录
- 创建 knowledge 记录及 attachments 记录
- 通过 ShareAbilityResultCode 返回或关闭分享面板

真机测试场景：

| 场景 | 验证点 | 通过标准 |
|---|---|---|
| 相册分享单图 | 分享入口、URI、复制、入库 | 私有文件存在且附件记录正确 |
| 相册分享多图 | 多记录解析与顺序 | 所有图片逐一复制并入库 |
| 浏览器分享链接 | content 与 URL 提取 | 条目中保留文本和 URL |
| 文本应用分享文字 | 纯文本接收 | 无图片也能创建条目 |
| 取消分享 | 会话退出 | 返回分享面板且应用不崩溃 |
| 图片复制失败 | 错误反馈 | 不显示虚假成功 |

特别注意：分享 URI 权限会在 ShareExtensionAbility 销毁后回收，因此图片复制必须在分享确认页关闭前完成。

### 原型 B：端侧 OCR

当前实现：

- textRecognition.init 初始化
- 图片尺寸检查和超大图片降采样
- recognizeText 识别
- API 21 错误码分类
- PixelMap、ImageSource 和 OCR 服务释放
- 单图和最多 20 张批量测试及耗时统计

测试图片建议：

- 聊天截图 5 张
- 短视频标题或字幕截图 5 张
- 文章或新闻截图 5 张
- 低清晰度、复杂背景或中英文混排截图 5 张

记录每张图片的识别成功、是否为空、主要错字、识别耗时和错误码。建议通过标准为至少 15/20 张获得可编辑的有效文本，平均耗时小于 5 秒。

### 原型 C：中文搜索

当前实现采用参数化 LIKE 查询，覆盖 content、keywords 和 note 字段。测试页生成 100 条带关键词数据，支持中文、英文和零结果查询，并展示耗时。

测试查询至少包括：

- 鸿蒙
- HarmonyOS
- 数据库
- ArkTS
- 不存在的词
- 特殊字符

通过标准：生成 100 条数据成功；已知关键词召回正确；单次查询小于 500ms；空结果和特殊输入不崩溃。

FTS4/ICU 当前没有实现，不得将 LIKE 原型的结果表述为 FTS4 已验证。只有数据量增大或 LIKE 性能不满足要求时，才单独建立 FTS 可用性原型。

## 4. Go/No-Go 标准

只有以下条件全部满足，才进入第 1 阶段：

- 系统分享核心场景能够完成真实文件复制和入库
- OCR 至少 15/20 张返回可用文本，且性能可接受
- LIKE 搜索在 100 条基线数据中结果正确且小于 500ms
- 所有失败场景均有明确记录，没有虚假成功状态

真机测试前，本项目的结论仍为“代码可构建，技术验证待完成”，不能标记为正式 Go。
