# KnowClip 技术验证原型完善设计

## 目标

将现有第 0 阶段工程完善为可构建、可安装、可在 HarmonyOS NEXT 真机上分别验证系统分享接收、端侧 OCR 和中文搜索的原型项目。本轮不扩展为完整 MVP，也不实现文件夹、标签、备份等后续功能。

## 实施范围

### 原型 A：系统分享接收

- 使用 `ShareExtensionAbility` 和 `type: "share"` 注册系统分享扩展。
- 用明确的 `ShareData` 类型解析图片 URI、文本和链接，避免 ArkTS 不支持的动态类型与类型谓词。
- 通过 `LocalStorage` 将分享数据传给确认页。
- 用户确认后立即把共享图片复制到应用私有目录，并创建 `pending` 知识条目与附件记录。
- 成功或失败均在确认页给出明确状态，最后通过 UIExtension session 正常退出。

### 原型 B：端侧 OCR

- 调用 CoreVisionKit 的真实 `textRecognition.init()`、`recognizeText()` 和 `release()`。
- 保留超大图片降采样，确保 `PixelMap` 与 `ImageSource` 在完成后释放。
- 按当前 SDK 声明处理错误码 `200`、`401`、`1001400001`、`1001400002`。
- 测试页面支持单张和多张图片，记录成功率、空结果与耗时。

### 原型 C：中文搜索

- 使用 RDB `insert()` 返回真实行 ID，所有入参使用显式接口。
- 本轮以 `LIKE` 作为确定可运行的基线方案，支持内容、关键词和笔记字段搜索。
- 插入 100 条带关键词的数据，保证页面状态可响应刷新，并记录查询耗时。
- FTS4/ICU 仍作为后续独立验证项，不在未验证系统支持前伪装成已实现能力。

## 数据流

系统分享数据进入 `ShareExtAbility` 后转换为 `ShareData`，通过 `LocalStorage` 传入 `ShareConfirmPage`。确认页调用文件服务复制附件，再调用数据库服务写入知识条目和附件。OCR 原型从 Photo Picker 获取 URI，交由 OCR 服务识别。搜索原型生成测试数据写入同一 RDB，再通过 LIKE 查询并展示结果与耗时。

## 错误处理

- 所有外部 API 调用在业务边界捕获 `BusinessError`，转换为用户可读信息。
- 分享保存采用逐项结果记录；单个文件失败不得伪装为保存成功。
- OCR 初始化失败、识别失败和空结果分别记录。
- RDB 结果集必须在 `finally` 或读取完成后关闭。

## 验证标准

- Hvigor `assembleHap` 达到 `0 errors`。
- 首页可以进入三个原型测试页。
- 原型 A 能在真机分享面板显示，并至少完成图片或文本的一次真实入库。
- 原型 B 能对真实截图返回文本或明确的 SDK 错误。
- 原型 C 能生成 100 条数据并完成中文、英文和零结果查询。
- README 与第 0 阶段文档如实区分“已实现”和“待真机验证”。

## 非目标

- 不实现完整知识库首页、详情编辑、标签、文件夹与备份恢复。
- 不加入云端 API、远程依赖或跨设备同步。
- 不在本轮对未确认支持的 FTS4/ICU 作产品承诺。
