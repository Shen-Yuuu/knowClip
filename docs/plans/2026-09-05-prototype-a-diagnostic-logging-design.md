# 原型 A 端到端诊断日志设计

## 背景

真机日志只显示主进程 `EntryAbility` 进入后台，没有出现分享扩展自身的日志。由于分享扩展可能运行在独立进程，仅凭当前日志无法判断失败发生在扩展创建、分享数据解析、确认页加载、图片复制、数据库保存还是会话关闭阶段。

## 目标

为原型 A 的完整执行链路增加可检索、可关联且不泄露分享内容的诊断日志。所有新增日志以 `[原型A]` 为首字段，使 DevEco Studio 或 hilog 可以通过该字符串过滤。

## 日志范围

- `ShareExtAbility`：扩展生命周期、会话创建、Want 摘要、Share Kit 调用开始与结果、SharedRecord 元数据、归一化结果、LocalStorage 写入、确认页加载及失败。
- `ShareConfirmPage`：页面出现、接收数据摘要、取消、保存开始、应用上下文、图片复制汇总、数据库初始化、知识条目写入、附件写入、保存结果和异常。
- `FileService`：每张共享图片的复制开始、源 URI 协议、源文件打开、目标文件打开、复制完成、文件大小、耗时及失败阶段。
- `ShareSessionService`：会话登记、清理、关闭请求、无会话和关闭成功或失败。

## 格式和隐私

统一格式为 `[原型A][阶段] 消息`。不输出完整 URI、分享文本、数据库内容或完整沙箱路径；只记录 URI 协议、字段是否存在、记录数量、图片数量、文本长度、数据库 ID、字节数、耗时和错误类型。系统时间、进程号和日志级别继续由 hilog 提供。

## 实现边界

不改变分享目标配置、业务数据结构、页面布局、文件保存规则和数据库行为。纯函数 `ShareDataParser` 保持无日志副作用，解析前后的摘要由调用方记录。

## 验证

运行现有 Hypium 单元测试和 `assembleHap`。真机复测时应能使用 `[原型A]` 一次过滤出从 `ShareExtAbility.onCreate` 到保存或关闭的完整关键路径；如果完全没有该前缀，则说明日志采集仍限定在主进程，或系统没有创建分享扩展。
